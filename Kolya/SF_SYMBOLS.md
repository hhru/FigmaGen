# SF Symbols Generation

This document describes the multicolor SF Symbols pipeline for developers maintaining or consuming the generated assets.

The SF Symbols pipeline is separate from the monochrome icon-font pipeline. It exists because colored icons need two independently configurable colors on iOS. The generated symbols use SF Symbols Palette rendering, where black Figma paths become the primary layer and red paths become the secondary layer.

## Main Points

- Figma remains the source of icon geometry.
- Only `colored=true` variants from the configured `icon` page and `icon` frame are included.
- Every symbol requires separate 16 px and 24 px optical drawings.
- The 16 px drawing is not generated by scaling the 24 px drawing.
- Black paths map to the Palette primary color.
- Red `#FF0002` paths map to the Palette secondary color.
- The 16 px drawing is stored as the `Regular-S` symbol variant.
- The 24 px drawing is stored as the `Regular-M` symbol variant.
- Both variants are designed for a 24-point base symbol configuration.
- SF Symbols do not provide a persistent four-sided image canvas. iOS layout must provide the final `16×16` or `24×24` frame.
- Do not use `.resizable()` to size these symbols. It scales visible path bounds and changes the relationship between artwork and its original Figma box.

## Pipeline

```text
Figma library
→ find colored component sets
→ select size=16 and size=24, colored=true
→ export raw SVG files
→ validate SVG features and colors
→ convert evenodd geometry to nonzero paths
→ map paths to Palette layers
→ transform optical drawings into SF Symbols coordinates
→ generate Template v3 SVG symbolsets
→ generate an Xcode asset catalog
→ write a geometry and validation report
```

Run the complete pipeline with:

```bash
npm run symbols:build
```

The command loads `FIGMA_TOKEN` from `.env.local` through Node's `--env-file` option.

## Source Requirements in Figma

The configured source is defined in `magritte-sf-symbols.config.ts`:

- Figma file key: `figmaFileKey`
- Page: `icon`
- Top-level frame: `icon`
- Name prefix: `icon`
- Required optical sizes: `16` and `24`

A component set is eligible only when its component property definitions contain a `colored` variant with a `true` option.

For every eligible component set, the pipeline requires:

```text
size=16, colored=true
size=24, colored=true
```

The component height must equal its configured optical size. Width may vary. A `27×16` component is valid for the 16 px optical size, and a `37×24` component is valid for the 24 px optical size.

The component box is the source of layout dimensions. The visible paths are not used to infer the component width or height. This preserves intentional Figma padding and non-square proportions during coordinate conversion.

Generated names use the configured prefix plus the component-set name. Name normalization is handled by `src/names.ts`.

## Color and Layer Mapping

The pipeline currently supports two source colors:

| Figma color | SF Symbols role |
| --- | --- |
| Black, `#000`, or `#000000` | Primary |
| `#FF0002` | Secondary |

Every SVG path must use one of these fills. Unknown or missing fills fail the build.

Each optical size must contain the same sequence of Palette roles. For example, if the 16 px drawing exports paths as `primary, secondary, primary`, the 24 px drawing must export the same role sequence. This requirement keeps SF Symbols layer annotations synchronized across variants.

The path geometry may differ between optical sizes, but path count and role order must remain compatible.

## SVG Validation

Raw SVGs are exported to:

```text
cache/sf-symbols-raw/16/
cache/sf-symbols-raw/24/
```

The SF Symbols pipeline accepts filled paths and rejects features that cannot be represented safely in the generated symbol template.

Rejected features include:

- Raster images
- Gradients
- Masks
- Filters
- Patterns
- `<style>` elements in Figma input
- Strokes other than `stroke="none"`
- SVG transforms in Figma input
- Unsupported fill colors
- Paths without `d` data

Figma may export compound paths with `fill-rule="evenodd"`. SF Symbols and downstream path processing can interpret these contours differently, causing holes to disappear or outlined shapes to become filled. `src/svg-path-winding.ts` converts evenodd geometry to nonzero-compatible filled paths before template generation.

Path export and transformation use six decimal places. Boolean conversion can still change extreme bounds by a small fraction. The validation report records the resulting artwork dimensions so unexpected changes can be detected.

## Optical Size Mapping

The project intentionally uses SF Symbols scale variants to store two different Figma optical drawings:

| Figma drawing | Template variant | Design-box scale |
| --- | --- | --- |
| 16 px | `Regular-S` | `16 / 24` |
| 24 px | `Regular-M` | `1` |

The 16 px drawing is therefore `0.666667` of the 24 px drawing in template coordinates. This is intentionally different from Apple's standard Small scale factor of `0.783`. The goal is to represent the design system's exact 16:24 optical-size relationship, not to reproduce Apple's default S:M emphasis ratio.

Both variants are selected from one symbol name. The application chooses the optical drawing through `.imageScale(.small)` or `.imageScale(.medium)`.

## Template Geometry

SF Symbols templates use typographic coordinates rather than image pixels.

The generator currently uses:

```text
Em design height: 100
Cap height:       70.459
Regular center X: 1449.845
Visual center Y:  -35.2295
```

The 24 px Figma component box maps to a 100-unit design box. The 16 px component box maps to a 66.667-unit design box. Non-square widths are scaled proportionally from the source component dimensions.

For each variant, the generator:

1. Calculates the destination design-box width and height.
2. Uniformly scales every path from Figma coordinates.
3. Vertically centers the component box around the SF Symbols cap-height center.
4. Horizontally centers the component box in the Regular template column.
5. Places left and right margin guides at the transformed component-box edges.
6. Places the resulting paths under `Regular-S` or `Regular-M`.

The transform preserves the geometry's position relative to its Figma component box. It does not crop paths to their visible bounds.

## Bounding Boxes and iOS Layout

SF Symbols are typographic images. A symbol configured at 24 points is not guaranteed to report an intrinsic `24×24` image size. Baseline, cap-height alignment, path bounds, horizontal margins, and pixel rounding all affect the natural image dimensions.

Important limitations:

- SF Symbols support left and right margin guides.
- They do not provide equivalent top and bottom margin guides.
- Baseline and capline guides control vertical alignment with text; they do not define a fixed square canvas.
- Invisible paths must not be added to fake a square bounding box. SF Symbols treats invisible paths as real symbol outlines, which can break validation, Palette layers, or animations.
- An intrinsic size such as `24×25` can be correct even when the visible vector geometry matches the Figma drawing.

For standalone image layout, provide the final box in SwiftUI and clip the symbol to it:

```swift
Image("icon-image-hyperstar-outlined")
    .symbolRenderingMode(.palette)
    .foregroundStyle(primaryColor, secondaryColor)
    .font(.system(size: 24))
    .imageScale(.medium)
    .frame(width: 24, height: 24, alignment: .center)
    .clipped()
```

Use the Small master for the 16 px optical drawing:

```swift
Image("icon-image-hyperstar-outlined")
    .symbolRenderingMode(.palette)
    .foregroundStyle(primaryColor, secondaryColor)
    .font(.system(size: 24))
    .imageScale(.small)
    .frame(width: 16, height: 16, alignment: .center)
    .clipped()
```

Modifier order matters. Apply `.font(...)` and `.imageScale(...)` before `.frame(...)`. Apply debug borders after `.frame(...)` when inspecting the final layout box.

Do not use:

```swift
.resizable()
.scaledToFit()
```

Those modifiers size the visible image geometry rather than preserving the intended relationship between the optical drawing and its conceptual component box.

The same principle applies in UIKit: constrain `UIImageView` to the desired size, apply a symbol configuration, use centered content, and clip the image view when strict bounds are required.

## Generated Output

The build writes:

```text
dist/sf-symbols/
├── MagritteSymbols.xcassets/
│   ├── Contents.json
│   └── <symbol-name>.symbolset/
│       ├── Contents.json
│       └── <symbol-name>.svg
└── validation-report.json
```

Copy or reference `MagritteSymbols.xcassets` from the iOS project. Each `.symbolset` contains one generated Template v3 SVG with both optical variants and Palette layer annotations.

`validation-report.json` records:

- Symbol name
- Original Figma component-set name
- Optical size
- SF Symbols variant name
- Path count
- Figma source-box dimensions
- Generated design-box dimensions
- Generated visible-artwork bounds

The report is intended for build diagnostics and geometry comparisons. It is not consumed at runtime.

## Modules and Methods

### `magritte-sf-symbols.config.ts`

Defines the Figma source, optical-size mapping, cache paths, output paths, and accepted primary and secondary fill colors.

### `src/sf-symbol-cli.ts`

The command-line entry point. It loads configuration and credentials, creates the Figma API client, analyzes candidates, generates the asset catalog, and reports output paths.

### `src/sf-symbol-config.ts`

Defines `SfSymbolConfig` and `SfSymbolSizeConfig`, then dynamically loads `magritte-sf-symbols.config.ts`.

### `src/sf-symbol-analysis.ts`

`analyzeSfSymbols()`:

- Finds the configured page and frame.
- Selects component sets supporting `colored=true`.
- Finds required 16 px and 24 px variants.
- Validates component height.
- Preserves variable component width.
- Creates deterministic symbol names.
- Returns candidates sorted by name.

### `src/sf-symbol-generation.ts`

`generateSfSymbols()` orchestrates export, parsing, validation, template generation, asset-catalog generation, and report generation.

Important internal methods:

- `exportRawSvgs()` requests SVG export URLs, downloads files, and writes the raw cache.
- `parseVariant()` validates SVG dimensions and converts paths into primary or secondary layers.
- `validateSvgFeatures()` rejects unsupported SVG features.
- `validateSynchronizedLayers()` ensures both optical variants have compatible Palette layer order.
- `transformPath()` maps Figma path coordinates into SF Symbols template coordinates.
- `getDesignBox()` calculates scaled component-box dimensions.
- `getArtworkBounds()` measures generated visible path bounds for reporting.
- `renderSymbolTemplate()` writes the Template v3 SVG document.
- `renderMarginGuides()` writes per-variant horizontal margins.

### `src/svg-path-winding.ts`

`convertEvenoddPathToNonzero()` uses Paper.js boolean geometry to replace evenodd fill behavior with explicit nonzero-compatible contours.

### `src/figma-api.ts`

Provides Figma REST API access for node inspection, SVG export URL creation, and SVG download.

## Validation and Testing

Run static TypeScript validation:

```bash
npm run typecheck
```

After `npm run symbols:build`, verify:

1. `validation-report.json` has `status: "valid"`.
2. The expected number of symbols was generated.
3. Every symbol contains both optical variants.
4. Source and design-box aspect ratios are consistent.
5. Palette colors appear correctly in the SF Symbols app.
6. Symbols import into the Xcode asset catalog without warnings.
7. Primary and secondary colors can be changed independently on iOS.
8. Medium renders the 24 px optical drawing.
9. Small renders the 16 px optical drawing.
10. The final SwiftUI frame is exactly `24×24` or `16×16` after clipping.
11. Filled and outlined compound paths retain holes and internal cutouts.
12. Symbols are tested on `@2x` and `@3x` devices or simulators for rounding differences.

The generated asset catalog is deleted and recreated on every build. Re-import or replace old generated assets before testing; previously imported copies in the SF Symbols app do not update automatically.

## Common Problems

### Symbol is approximately 17 points at a 24-point font size

SF Symbols use typographic point sizes and cap-height alignment. A font point size does not guarantee matching screen dimensions. Inspect both the intrinsic symbol size and the final fixed SwiftUI frame before changing generator geometry.

### Symbol reports `24×25`

This can happen because of baseline placement and fractional raster bounds. If the visible vector matches Figma, keep the generated geometry and use `.frame(width: 24, height: 24).clipped()`.

### Padding disappears after resizing

`.resizable()` scales visible path bounds. Empty Figma padding is not a four-sided SF Symbols canvas. Use symbol configuration plus a fixed container instead of geometric resizing.

### Palette colors are reversed

Check the Figma fills and path order. Black must represent primary and `#FF0002` must represent secondary. Review the generated path classes and `validation-report.json`.

### Import succeeds but holes become filled

Inspect the raw SVG for `fill-rule="evenodd"`, then verify the generated template contains nonzero-compatible contours. Do not bypass `convertEvenoddPathToNonzero()`.

### Variants fail layer synchronization

Ensure both optical drawings export the same path count and the same primary/secondary role order. Grouping paths differently between 16 px and 24 px can change Figma export order.

## Invariants for Future Changes

- Do not derive the 16 px drawing by scaling the 24 px SVG.
- Do not add unsupported colors without defining their SF Symbols role.
- Do not silently reorder Palette layers.
- Do not infer layout size from visible path bounds.
- Do not add invisible square paths to simulate a canvas.
- Do not translate or resize individual icons to fix application layout problems.
- Keep generated names deterministic.
- Keep raw exports available for debugging.
- Keep build failures explicit for unsupported SVG features.
- Validate changes in SF Symbols and on iOS, not only in a browser SVG renderer.
